# Prompt 收藏夹 — 最终软件设计方案

**文档版本**：1.0  
**状态**：设计定稿，可对照开发  
**存储方式**：纯文件，无数据库  
**目标平台**：WPF 桌面应用（设计通用，可移植）  
**核心定位**：本地优先的 Prompt 片段管理器。核心动作：一键复制、直接编辑、收藏筛选。

---

## 1. 产品概述

Prompt 收藏夹是一个本地桌面工具，用于存放、编辑、检索和快速复制常用的 AI Prompt。它不依赖网络，不使用数据库，所有数据以 Markdown 文件形式存放在本地文件夹中。用户可以直接用文件管理器或 Obsidian 查看、编辑、备份这些文件。

产品设计围绕三个高频动作：

1. **复制**：最短路径将 Prompt 正文送入剪贴板。
2. **编辑**：在右栏直接修改正文与元数据，点击保存落盘。
3. **收藏与排序**：在中栏按当前模块筛选收藏项，并按使用次数、修改时间等排序。

---

## 2. 术语定义

| 术语         | 含义                                                         |
| ------------ | ------------------------------------------------------------ |
| 模块         | 左栏中的分类，对应文件系统中的一个文件夹                     |
| 条目         | 一个 Prompt，对应一个 `.md` 文件                             |
| 正文         | 文件中 frontmatter 之后的内容，即用户真正要复制的 Prompt     |
| frontmatter  | 文件开头由 `---` 包裹的 YAML 元数据区                        |
| 权威来源     | 文件夹名 = 模块名，文件名 = 标题；frontmatter 中的对应字段是派生副本 |
| 收藏         | 条目的一个布尔属性，`favorite`                               |
| 使用次数     | `useCount`，每次复制加一                                     |
| 最后使用时间 | `lastUsedAt`，每次复制更新                                   |
| 修改时间     | `updatedAt`，仅在保存正文/标题/模块变更时更新                |
| 创建时间     | `createdAt`，新建条目时设置，不再变更                        |

---

## 3. 总体架构与存储

### 3.1 存储原则

- **纯文件，无数据库**。
- 每个条目一个 `.md` 文件，frontmatter + 正文。
- 模块即文件夹，条目即文件。
- 备份 = 复制整个 `Prompts` 文件夹。
- 用户可直接在外部编辑文件，程序启动时自愈。

### 3.2 目录结构

```text
Prompts/
├── 写作/
│   ├── 无损转录器.md
│   └── 分块生成.md
├── 编程/
│   └── 代码审查.md
└── 翻译/
    └── 逐段翻译.md
```

- `Prompts` 为根目录，位置可由用户配置。
- 模块文件夹名即模块名。
- 文件名（不含 `.md`）即条目标题。

### 3.3 文件格式

每个 `.md` 文件结构：

```markdown
---
title: 无损转录器
module: 写作
favorite: true
useCount: 42
createdAt: 2025-01-01T10:00:00
updatedAt: 2025-01-10T15:30:00
lastUsedAt: 2025-01-10T15:30:00
---

你是无损转录器，不是总结器……

硬性规则：
1. 不得总结、改写、删减……
```

### 3.4 frontmatter 解析规则

- 程序读取文件开头。
- 如果第一行是 `---`，继续向下寻找下一个 `---`。
- 两个 `---` 之间的内容为 frontmatter。
- 第二个 `---` 之后的所有内容为正文。
- 正文中出现的 `---` 只要不在文件开头，不视为 frontmatter 分隔符。
- 如果文件没有 frontmatter，程序按默认值补全。

### 3.5 数据字段定义

| 字段         | 类型    | 说明         | 权威来源             |
| ------------ | ------- | ------------ | -------------------- |
| `title`      | string  | 条目标题     | 文件名（派生副本）   |
| `module`     | string  | 所属模块     | 文件夹名（派生副本） |
| `favorite`   | bool    | 是否收藏     | 程序维护             |
| `useCount`   | int     | 使用次数     | 程序维护             |
| `createdAt`  | ISO8601 | 创建时间     | 程序维护             |
| `updatedAt`  | ISO8601 | 修改时间     | 程序维护             |
| `lastUsedAt` | ISO8601 | 最后使用时间 | 程序维护             |

## 4. 界面布局

### 4.1 整体三栏布局

```text
┌─────────────────────────────────────────────────────────────────────┐
│  [搜索框]                                                           │
├──────────┬──────────────────────────────────┬───────────────────────┤
│  模块     │  [★收藏] [次数][修改][创建][名称]  │  详情 + 编辑          │
│          │  ──────────────────────────────── │                       │
│  写作     │  ● 无损转录器          42次  ★   │  标题：[无损转录器]    │
│  编程     │  ○ 分块生成            31次      │  模块：[写作] ★       │
│  翻译     │  ○ 代码审查            18次      │  ───────────────      │
│  头脑风暴 │                                  │  正文编辑区            │
│          │                                  │                       │
│  [+]     │  [+]                             │  [复制] [保存]         │
└──────────┴──────────────────────────────────┴───────────────────────┘
```

- 顶部：搜索框，通栏，跨模块搜索。
- 左栏：模块列表。
- 中栏：当前模块下的条目列表 + 控制条（收藏、排序）。
- 右栏：详情与编辑区。

### 4.2 窗口尺寸

- 默认尺寸、最小尺寸、各栏宽度待实现时再定。
- 建议左栏固定约 200px，中栏约 260–320px，右栏自适应。
- 最小宽度建议不低于 900px，避免三栏过挤。

## 5. 左栏（模块栏）详细设计

### 5.1 内容

- 平铺模块列表，每个模块对应一个文件夹。
- 不设“全部”特殊项。
- 不设“收藏”特殊项。
- 支持两种排序：**创建日期**（默认，按目录创建时间降序，新建在前）与**名称**（不区分大小写升序）。排序按钮放在标题下方第二行，样式与中栏排序条一致（详见第 9 节）。
- 启动时默认选中上次打开的模块，或第一个模块。
- 允许存在空文件夹（空模块）。

### 5.2 顶部操作

- 顶部 `+` 按钮：新建模块。
  - 点击后创建空文件夹。
  - 名称由用户输入，默认可为“未命名模块”。
  - 创建后左栏刷新，并选中新模块。

### 5.3 右键菜单

右键点击模块，弹出菜单，仅两项：

1. **重命名**
2. **删除**

#### 重命名

- 弹窗：标题“重命名模块”，输入框自动全选当前名字。
- 回车 = 确认，Esc = 取消。
- 名字为空时，确认按钮置灰。
- 与同级模块重名时，提示“已存在同名模块”。
- 确认后：
  - 文件夹改名。
  - 该文件夹下所有 `.md` 文件的 `module` 字段更新为新模块名。
  - 左栏刷新。
  - 中栏如果当前显示该模块，刷新标题。
  - 右栏如果当前条目的模块是该模块，元数据区同步更新。

#### 删除

- 如果模块下有内容（存在 `.md` 文件）：
  - 删除菜单项置灰。
  - 鼠标悬浮显示灰色提示：“该模块下还有条目，请先移动或删除”。
- 如果模块为空：
  - 删除可点。
  - 弹窗确认：“确定删除模块‘XXX’吗？此操作不可撤销。”
  - 按钮：[取消] [删除]，默认焦点在“取消”，“删除”用警示色。
  - 确认后删除文件夹，左栏刷新。

## 6. 中栏（条目列表）详细设计

### 6.1 顶部控制条

位于中栏顶部，搜索框下方。包含：

- **收藏按钮**：切换按钮，点击开启/关闭。
- **排序按钮组**：四个按钮，单选，点击即生效。
  - 使用次数
  - 修改时间
  - 创建时间
  - 名称

布局可一行或两行，视宽度自适应。

### 6.2 收藏筛选规则

- 收藏按钮开启时，只显示**当前左栏选中模块内** `favorite = true` 的条目。
- 收藏按钮关闭时，显示当前模块全部条目。
- 点击条目的星标可切换收藏状态，**立即写回文件**，不经过保存按钮。
- 收藏/取消收藏**不更新** `updatedAt`。
- 收藏状态变化后，中栏列表实时刷新（如果收藏筛选开启，取消收藏的条目会消失）。

### 6.3 排序规则

- 默认排序：使用次数降序。
- 使用次数相同时：按 `updatedAt` 降序。
- 其他排序：
  - 修改时间：按 `updatedAt` 降序。
  - 创建时间：按 `createdAt` 降序。
  - 名称：按标题字典序升序。
  - 自定义：按本地记录的拖动顺序，规则见 9.3。
- 排序按钮单选，点击即切换，中栏列表立即重排。
- 收藏筛选与排序可同时生效。

### 6.4 列表项显示

- 标题。
- 使用次数（如“42次”）。
- 星标（收藏状态）。
- 悬停时显示复制图标。
- 点击条目：右栏显示详情。
- 点击星标：切换收藏，立即写回。

### 6.5 顶部新建条目

- 中栏顶部 `+` 按钮：在当前模块下新建条目。
- 默认文件名“未命名.md”。
- 创建后：
  - 新条目自动进入右栏编辑状态。
  - 光标落在标题输入框。
  - `useCount = 0`，`favorite = false`，`createdAt` 和 `updatedAt` 设为当前时间。
  - 中栏刷新并选中新条目。

### 6.6 右键菜单

右键点击条目，弹出菜单，仅两项：

1. **重命名**
2. **删除**

#### 重命名

- 弹窗：标题“重命名条目”，输入框自动全选当前名字。
- 回车 = 确认，Esc = 取消。
- 名字为空时确认置灰。
- 与同模块下其他条目重名时，提示“已存在同名条目”。
- 确认后：
  - 文件改名。
  - `title` 字段更新。
  - 中栏和右栏刷新。

#### 删除

- 弹窗确认：
  - 标题“删除条目”。
  - 内容：“确定删除‘无损转录器’吗？此操作不可撤销。”
  - 按钮：[取消] [删除]，默认焦点在“取消”，“删除”用警示色。
- 确认后：
  - 删除文件。
  - 中栏刷新。
  - 如果右栏当前显示的是该条目，右栏清空。

### 6.7 搜索时的行为

- 搜索框激活时：
  - 左栏模块高亮取消。
  - 中栏显示全局搜索结果（跨模块）。
  - 收藏按钮如果开着，过滤搜索结果中的收藏项。
  - 排序按钮作用于搜索结果。
- 搜索关闭后：
  - 恢复到当前模块视图。
  - 收藏和排序状态保留。

## 7. 右栏（详情 + 编辑）详细设计

### 7.1 元数据区（可折叠）

#### 展开状态

显示以下字段：

- 标题：可编辑输入框。
- 模块：可编辑下拉框（列出所有模块）。
- 收藏：星标按钮。
- 使用次数：只读。
- 创建时间：只读。
- 修改时间：只读。

#### 折叠状态

只显示一行摘要：

```text
标题 · 模块 · ★ · [展开]
```

- 折叠状态记住，下次打开同一条目或同一模块时保持。
- 折叠按钮用小三角，放在标题行右侧。

### 7.2 正文编辑区

- 只显示正文，不显示 frontmatter。
- frontmatter 完全由程序在背后维护。
- 用户在此区域编辑 Prompt 正文。

### 7.3 底部按钮

仅保留两个按钮：

1. **复制**
2. **保存**

不做删除，不做派生。

#### 保存按钮状态

| 状态         | 保存按钮     |
| ------------ | ------------ |
| 无变更       | 置灰，不可点 |
| 有未保存变更 | 可点         |

- 快捷键 `Ctrl+S`：与点击「保存」完全等价，走同一条命令、同一套可用性判断（无变更时不响应，按钮置灰也不响应）。
  - 生效范围 = 右栏：焦点在正文编辑区或元数据输入框时可用；焦点在左栏/中栏时该组合键不被拦截，也不触发保存。
  - 实现见 `Views/EntryDetailView.xaml` 的 `UserControl.InputBindings`（绑定到既有的 `SaveCommand`）。

- 保存时：
  1. 写 frontmatter + 正文。
  2. 如果标题变了，改文件名，并更新 `title`。
  3. 如果模块变了，移动文件到对应文件夹，并更新 `module`。
  4. 更新 `updatedAt`。
  5. 刷新中栏和左栏。
  6. 保存按钮恢复置灰。

#### 复制按钮状态

| 状态         | 复制按钮                   |
| ------------ | -------------------------- |
| 无未保存变更 | 可点，直接复制             |
| 有未保存变更 | 可点，但点击弹窗提示先保存 |

- 复制内容 = **纯正文**，不含 frontmatter，不含任何元数据字段。
- 复制时后台更新：
  - `useCount + 1`
  - `lastUsedAt = now`
  - **不更新** `updatedAt`
- 复制成功后：
  - 轻提示，例如按钮短暂变“已复制 ✓”或顶部淡入提示。
  - 列表不立即重排，避免视觉跳动。

#### 有未保存变更时点击复制

- 弹窗提示：“有未保存的更改，请先保存后再复制。”
- 按钮：[保存] [取消]
  - 点“保存”：只保存，不自动复制。弹窗关闭，复制按钮恢复可点，用户可再次点击复制。
  - 点“取消”：弹窗关闭，不保存，不复制。

#### 未保存切换条目

- 如果右栏有未保存更改，用户点击其他条目时：
  - 弹窗提示：“有未保存更改，是否放弃？”
  - 按钮：[放弃] [取消]
  - 点“放弃”：丢弃更改，切换到新条目。
  - 点“取消”：留在当前条目。

## 8. 搜索与筛选

### 8.1 搜索框

- 位置：窗口顶部通栏。
- 范围：跨模块搜索标题和正文。
- 行为：
  - 输入关键词后，中栏显示全局搜索结果。
  - 左栏模块高亮取消。
  - 收藏按钮如果开启，过滤搜索结果中的收藏项。
  - 排序按钮作用于搜索结果。
  - 清空搜索框后，恢复当前模块视图，收藏和排序状态保留。

### 8.2 收藏筛选

- 范围：当前左栏选中模块内。
- 开关：中栏顶部收藏按钮。
- 点击条目星标：立即写回文件，不更新 `updatedAt`。

## 9. 排序规则

### 9.1 中栏（条目）

| 排序方式         | 规则                                     |
| ---------------- | ---------------------------------------- |
| 使用次数（默认） | `useCount` 降序；相同则 `updatedAt` 降序 |
| 修改时间         | `updatedAt` 降序                         |
| 创建时间         | `createdAt` 降序                         |
| 名称             | 标题字典序升序                           |
| 自定义           | 按本地记录的标题顺序表排列，见 9.3       |

### 9.2 左栏（模块）

| 排序方式         | 规则                                                       |
| ---------------- | ---------------------------------------------------------- |
| 创建日期（默认） | 目录创建时间降序（新建在前）；相同则按名称升序             |
| 名称             | 目录名不区分大小写升序                                     |
| 自定义           | 按本地记录的目录名顺序表排列，见 9.3                       |

- 模块就是磁盘目录，创建时间取 `Directory.GetCreationTime`。
- 切换排序只重排左栏，不改变当前选中的模块，也不重新加载中栏条目（避免冲掉右栏未保存的编辑）。

### 9.3 自定义顺序（拖动排序）

两栏各有独立的"自定义"排序，且**只有处于该排序时**才能上下拖动行；另外四种排序不可拖。

- 顺序只存本地配置，不写进 `.md` 或目录：把数据文件夹拷到别的机器、或用资源管理器手动改名，顺序不会跟过去，丢了也不影响内容。
- 顺序按**名字**（目录名 / 条目标题）记录，不按下标，因此新建、删除、外部拷入都不会让整表错位。
- **只有拖动落下才写配置，且立即落盘**；点"自定义"这个动作本身不产生任何写入。
- 从没拖过的栏或模块点"自定义"：以切换前看到的那份顺序为起点（只留在内存），不写配置；第一次拖动才固化。
- 表里没有的名字排在已记录项之后，彼此保持读入顺序（即名称升序）；读取配置时绝不回写。
- 重命名会同步换掉表里的名字、位置不变：条目改名（中栏右键改名与右栏改标题两条路径都算）、模块改名（同时把它名下的条目顺序表搬到新模块名下）。
- 删除不动配置；残留在表里的名字在下次拖动写回时被剔除。
- 开着收藏筛选或搜索时禁止拖动：那时看到的是子集，用子集覆盖整表会打乱未显示项的顺序。
- 顺序文本与其他设置同文件；若超过约 32 KB 则只丢顺序、保留其余设置（并记 `diagnostics.log`），不让整个设置写不进去。
- 存储格式（kv1，值不转义）：分隔符取 Windows 文件名的非法字符 `|`、`>`、`:`，模块名与标题都不可能含它们，因此编解码严格互逆、无需转义。

```text
moduleCustomOrder=模块A|模块B|模块C
entryCustomOrder=模块A:标题1|标题2>模块B:标题3
```

两栏共同规则：

- 排序按钮单选。
- 收藏筛选与排序可同时生效。
- 复制后列表不立即重排，避免视觉跳动。
- 两栏的排序选择都在关窗时写入设置（`sortMode` / `moduleSortMode`），下次启动恢复；自定义顺序本身则在拖动落下时即时写入（见 9.3）。

## 10. 复制规则（最终版）

- 复制内容 = **纯正文**，不含 frontmatter，不含标题、模块、使用次数、时间等任何元数据。
- 实现：解析文件时，取第二个 `---` 之后的所有内容作为正文。右栏编辑区显示的也是这段。
- 复制按钮复制的是**右栏正文编辑区的当前文本**。
- **无未保存更改时**：复制按钮可点，点击直接复制。
- **有未保存更改时**：点击复制 → 弹窗提示“有未保存的更改，请先保存后再复制。” → 按钮 **[保存] [取消]**
  - 点“保存”：保存当前更改，弹窗关闭，复制不执行。用户可再次点击复制。
  - 点“取消”：弹窗关闭，不保存，不复制。
- 复制成功后：
  - 进剪贴板。
  - 轻提示。
  - 后台更新 `useCount + 1`、`lastUsedAt = now`。
  - **不更新** `updatedAt`。
  - 列表不立即重排。

## 11. 保存规则

- 保存按钮：有变更可点，无变更置灰。
- 保存时依次执行：
  1. 读取原文件 frontmatter，保留程序字段（`createdAt`、`useCount`、`lastUsedAt` 等）。
  2. 用右栏的标题、模块、收藏更新 frontmatter 对应字段。
  3. 将 frontmatter + 正文重新拼成完整 Markdown。
  4. 写回文件。
  5. 如果标题变了，改文件名，并更新 `title`。
  6. 如果模块变了，移动文件到对应文件夹，并更新 `module`。
  7. 更新 `updatedAt`。
  8. 刷新中栏和左栏。
  9. 保存按钮恢复置灰。
- 如果第 5、6 步失败，正文已写入，但文件名或模块未改。下次启动扫描时以文件名、文件夹名为准自愈。

### 12.1 新建模块

- 左栏顶部 `+`。
- 创建空文件夹。
- 名称用户输入。

- 初始化字段：
  - `useCount = 0`
  - `favorite = false`
  - `createdAt = now`
  - `updatedAt = now`
  - `lastUsedAt = null` 或空

### 12.3 重命名模块

- 右键模块 → 重命名。
- 弹窗确认。
- 文件夹改名 + 所有文件 `module` 更新。

### 12.4 重命名条目

- 右键条目 → 重命名。
- 弹窗确认。
- 文件改名 + `title` 更新。

### 12.5 删除模块

- 有内容时删除置灰，悬浮提示。

### 12.6 删除条目

- 右键条目 → 删除。
- 弹窗确认，显示具体文件名。
- 默认焦点在“取消”。

## 15. 数据一致性与自愈

### 15.1 权威来源

- 文件夹名 = 模块名，是权威来源。
- 文件名 = 标题，是权威来源。
- frontmatter 里的 `title`、`module` 是派生副本。

### 15.2 启动扫描自愈

- 程序启动时扫描 `Prompts` 根目录下所有模块文件夹和 `.md` 文件。
- 对每个文件：
  - 以文件夹名为准修正 `module`。
  - 以文件名为准修正 `title`。
  - 如果 frontmatter 缺失字段，补默认值。
  - 如果 `createdAt` 缺失，设为文件创建时间或当前时间。
  - 如果 `useCount` 缺失，设为 0。
  - 如果 `favorite` 缺失，设为 false。
- 如果根目录下直接有 `.md` 文件，建议自动创建“未分类”模块并移入，或提示用户。此行为待定。

### 15.3 外部编辑

- 用户可在文件管理器或 Obsidian 中直接编辑文件。
- 程序不常驻监听时，通过“刷新”按钮或重启自愈。
- 刷新按钮位置待定，建议放在顶部工具栏或左栏底部。

### 15.4 改名顺序

- 先改文件夹名或文件名，再更新 frontmatter。
- 中途失败，靠启动扫描自愈。

## 21. 剪贴板实现说明（技术决策）

结论摘要（完整的问题报告：根因分层、方案取舍、两次误判、改动原理与实测数据见 [`剪贴板卡顿问题报告.md`](剪贴板卡顿问题报告.md)）：

1. 缺陷在组件库不在本应用：库内所有可编辑控件的复制/剪切/粘贴最终落到 WPF 的 `System.Windows.Clipboard`（OLE 通道，抢锁失败在调用线程重试），故"凡是可编辑文本组件，Ctrl+X 都卡约 2 秒"。
2. 修复落在库内：`UI4Clipboard`（原生 Win32 读写，写/读在后台线程重试后回投 UI 线程；`ContainsText()` 用 `IsClipboardFormatAvailable` 不参与抢锁）+ `Internal/ClipboardCommandTakeover`（`PreviewKeyDown` 隧道接管 Ctrl+C/X/V，装到 `UI4TextBox`/`UI4PasswordBox`/`UI4CodeEditor`/`UI4TextBlock`/`UI4DataGrid`）。
3. 只接在 `CommandBinding.PreviewExecuted` **拦不住真实按键**（实测仍阻塞约 2 秒），必须接按键隧道。
4. Notepad 式"所有权 + 延迟渲染"在本机不可用（延迟渲染声明固定失败），不采用。
5. 应用侧不保留任何剪贴板实现，复制按钮直接调 `UI4Clipboard.TrySetTextAsync`（`ViewModels/MainViewModel.cs:179`），失败提示留在应用层。

## 22. 设置持久化格式与损坏自愈（kv1）

背景事故：用户机器上 `%APPDATA%\PromptFavorites\settings.json` 膨胀到 **16,777,465 字节**，应用启动后进程存活但没有任何窗口。取证：文件仍是 10 行，只有 `rootPath` 一行长度 16,777,261 字符，其中反斜杠正好 **2²⁴ = 4 段 × 2²²** —— 原值 `C:\Users\webtu\Documents\Prompts` 的 4 个分隔符被翻倍了 22 次。

两个叠加缺陷（均属本应用实现层，与组件库/上游无关；设计文档此前只要求"记住上次模块/折叠/窗口/根目录"，未规定 JSON）：

| # | 缺陷 | 原位置 |
|---|---|---|
| D1 | 写用 `EscapeJson`（`\`→`\\`），读是自制解析器只 `Trim('"')` 从不反转义 → 每存一次反斜杠翻倍 | `Services/SettingsService.cs` 旧 :146-150（写）/ :50（读） |
| D2 | 脏路径 >260 字符 → `App.xaml.cs` 的 `Directory.CreateDirectory` 在建窗口**之前**抛 `PathTooLongException`；`App.xaml` 是 `ShutdownMode="OnMainWindowClose"` 且 `MainWindow` 为 null → 退出条件永不满足 → 无窗口僵尸进程 | `App.xaml.cs` 旧 :51-52 / :59-77 |

放大器：关一次窗连着 Save 两次（`MainWindow_Closing` 与 `App.OnExit`）→ 每重启约 ×4，约 11 次重启即到 16 MB。

现行约定：

1. **新格式 kv1**：`%APPDATA%\PromptFavorites\settings.json`，首行 `# PromptFavorites settings (kv1)`，其后每行 `key=value`，按第一个 `=` 切分，**值原样存储、不做任何编码**。写侧不转义、读侧不反转义，互逆性由构造保证（`Services/SettingsCodec.cs`）。不变量：值不含 CR/LF、首尾空格不保留 —— Windows 路径与目录名天然满足。
2. **旧 JSON 一次性兼容**：按首个非空白字符是否 `{` 识别，走 `ParseLegacyJson`（含旧 `EscapeJson` 的严格单遍逆函数 `UnescapeJson`，只认 `\\` 与 `\"`；`C:\notes` 不得被当成换行转义）+ `CollapseSeparators` 抢救已被放大的历史路径；首次保存即落为 kv1。
3. **启动不变量**：`App.OnStartup` 无论数据准备成功与否都必须以"有可见窗口"或"进程退出"结束；未处理异常时若已无窗口则显式 `Shutdown`。根目录不可用时窗口照常出现，之后才提示选目录，用户取消也不退出。
4. **容错三道防线**：文件 >64 KB 直接判损坏；解析异常或超限 → 改名留档 `settings.json.corrupt-<时间戳>.bak`（只改名不删除）并回默认值；`Save()` 内容未变则不写盘（消除重复写），且先写 `.tmp` 再覆盖避免半截文件。
5. **根目录合法性**：`Helpers/RootPathResolver.cs` 统一归一化与校验，长度上限 240（net48 未开系统长路径时受 MAX_PATH=260 限制，留余量给 `\模块名\标题.md`）；非法/超长/无权限一律返回 false 而非抛异常。`ChangeRootPath` 改为**先校验成功再落盘**。
6. **采集与写盘分离**：`MainViewModel.CaptureWindowState`（只写内存，最大化时不采集几何）与 `SaveWindowState`（采集 + 落盘）；`OnExit` 的 Save 靠内容幂等自动变 no-op。
7. `windowState` 纳入持久化（此前字段存在但从未写读，最大化状态每次重启丢失）；数值字段拒绝 NaN/Infinity 与越界；`rootPath` 为空时禁止新建模块（避免在 `bin\Debug\net48` 下建目录）。

验证方式（全部已跑通）：

- `PromptFavorites_self_contained.exe --selftest` → 退出码即失败断言数（含"连续 5 轮序列化文本长度不增"这条直接对指数膨胀设防的断言）。net10 迁移后打包产物按发布模式带文件名后缀，免运行时版为 `PromptFavorites_no_runtime.exe`，两者的 `--selftest` 退出码契约完全一致（实测都是 0）。
- 稳定性：连续 4 轮启动/关闭，`settings.json` 字节数与 SHA256 自第 2 轮起逐字节恒定（266 B）。
- 损坏注入 5 类（超长旧 JSON / 二进制垃圾 / 畸形文本 / 非法字符路径 / 不存在的合法目录）：每次都出窗口、无僵尸进程，超限那份被改名留档，设置重置为小体积 kv1。
