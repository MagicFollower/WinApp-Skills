# 窗口标题与应用图标设置教程

以本项目的 `Prompt 收藏夹 → 收藏夹` 改名 + 手绘图标接入为例，说明 WPF（.NET 10）里改标题、设图标要动哪几处，以及图标的两条链路各自管什么。文末是本轮实测数据。

## 一、改窗口标题

只有一处：`app/MainWindow.xaml` 里 `Window` 元素的 `Title`。

```xml
Title="收藏夹"
```

要点：

- 标题写在 XAML 里，不要在 `MainWindow.xaml.cs` 的构造函数里赋值——那要等 `InitializeComponent()` 之后才生效，会闪一下旧标题，而且 XAML 里那行还留着旧值，改一处漏一处。
- 代码里另有两处 `Title = "选择 Prompt 根目录"`（`App.xaml.cs:135`、`MainWindow.xaml.cs:132`），那是**目录选择对话框**的标题，与主窗口标题无关，别顺手一起改。
- 任务栏按钮、Alt+Tab、窗口列表读的都是同一个 `Window.Title`，不需要额外设置。

## 二、图标的两条链路

| 链路 | 配在哪 | 管什么 | 生效时机 |
|---|---|---|---|
| **exe 文件图标** | `csproj` → `<ApplicationIcon>` | 资源管理器、桌面快捷方式里的 exe 图标（本项目为 `PromptFavorites_self_contained.exe` / `PromptFavorites_no_runtime.exe`） | 编译期由 SDK 把 .ico 写进 apphost 的 `RT_GROUP_ICON` 资源段 |
| **窗口图标** | `MainWindow.xaml` → `Window.Icon` | 标题栏左上角、任务栏按钮、Alt+Tab 的窗口图标 | 运行期从程序集内嵌资源加载 |

```xml
<!-- app/PromptFavorites.csproj -->
<PropertyGroup>
  <ApplicationIcon>AppIcon.ico</ApplicationIcon>
</PropertyGroup>
<ItemGroup>
  <Resource Include="AppIcon.ico" />   <!-- Window.Icon 是 pack URI，必须嵌进程序集才取到 -->
</ItemGroup>
```

```xml
<!-- app/MainWindow.xaml -->
Icon="AppIcon.ico"
```

**两条链路不是并列必需的**（本轮实测纠正过）：只配 `<ApplicationIcon>`、把 `Window.Icon` 删掉重新构建，标题栏和任务栏**仍然是同一枚图标**——WPF 在 `Window.Icon` 为空时会回落到进程主模块（exe）的图标。所以：

- 只想要"应用有个图标"：配 `<ApplicationIcon>` 一处就够。
- 本项目两处都配，理由是不把窗口外观挂在回落行为上（将来有人给某个窗口单独设 `Icon`、或换不带图标的宿主时，症状是"图标悄悄变回默认"，很难查）。代价是 .ico 在包里存了两份，实测单文件 exe 体积 +447 KB。

`Window.Icon="AppIcon.ico"` 是相对 pack URI，读的是**程序集资源**，所以 `<Resource Include>` 那行不能省；`<ApplicationIcon>` 只是"烤进 exe"，不会自动变成可被 XAML 引用的资源。

另外，实测 `GCLP_HICON` / `GCLP_HICONSM`（窗口类图标）都为 0，说明 WPF 是通过**窗口级** `WM_GETICON` 供图的，不是设窗口类图标——排查时别去查类样式。

## 三、ICO 文件本身

### 为什么必须多尺寸

系统按用途挑尺寸：标题栏 16、任务栏 24/32、资源管理器 32/48、缩略图 256。ico 里缺哪挡，系统就拿别的缩放给你，症状是"图标发糊"而不是报错。本项目一次生成 7 挡：`16 / 24 / 32 / 48 / 64 / 128 / 256`。

### 生成脚本

> **2026-10-04 核对：本节的两条命令当前跑不了。** `tools\make-icon.ps1` 未随本包交付（`tools/` 目录整体不存在，机器上其它项目里的同名脚本是另一种实现——逐字母点阵，不是本项目的书签+星）。下面的命令与参数保留作为设计记录；要换图标请**直接整体替换 `app\AppIcon.ico`**（保持多尺寸、7 挡那份的结构），并同步 csproj 的 `<ApplicationIcon>` 与 `<Resource Include>` 两处引用。

```
powershell -ExecutionPolicy Bypass -File tools\make-icon.ps1
powershell -ExecutionPolicy Bypass -File tools\make-icon.ps1 -PreviewDir _icon_preview
```

输出 `app\AppIcon.ico`；`-PreviewDir` 额外导出各尺寸 PNG 和一张接触表，用来肉眼确认小尺寸还认得出来。

图标是脚本里用 GDI+ 矢量图元手绘的，不依赖任何外部图片：蓝色竖向渐变圆角徽底 + 白色书签（顶部两角圆角、底部 V 缺口）+ 偶奇填充镂空的五角星。两个实现细节值得抄：

- **超采样再逐级折半**：先在 1024 画布上画，再 `/2`、`/2` 缩到目标尺寸。一步 bicubic 从 1024 缩到 16 会糊，逐级折半相当于做了面积平均。
- **小尺寸视觉简化**：镂空星只有 31/256，缩到 24px 以下会糊成脏点，所以 16/24 两挡改用实心书签（`Render-Base` 的 `$detailed` 参数）。同一枚图标在不同尺寸上换细节是常规做法，不是将就。

### ICO 二进制结构（手写时最容易错的 4 点）

```
ICONDIR        reserved=0  type=1  count
ICONDIRENTRY[] width, height, 0, 0, planes=1, bitCount=32, bytesInRes, imageOffset
每挡 image     BITMAPINFOHEADER(biSize=40, biWidth=w, biHeight=w*2, BI_RGB)
               + BGRA 像素（自下而上）
               + AND 掩码（1bpp，行补齐到 4 字节）
```

1. 256 这一挡的 `width`/`height` 字节要写 **0**（历史约定 `0 = 256`），但 `biWidth`/`biHeight` 仍写真实的 256/512。
2. `biHeight` 是**两倍高**：BMP 段里 XOR 位图 + AND 掩码按高度叠加计算。
3. 32bpp 且像素带 alpha 时 AND 掩码被系统忽略，全 0 即可——但仍要按行占位，`bytesInRes` 得把它算进去。
4. 像素行序要翻转：`LockBits` 给的是自上而下，ICO 要自下而上。

## 四、常见坑

1. **改了图标但资源管理器里没变** —— 先确认新 exe 里确实有图标资源（跑 `tools\verify-icon.ps1` 看 `(1)`；**该脚本未随本包交付**，替代做法：`[System.Drawing.Icon]::ExtractAssociatedIcon(<exe>)` 取回内嵌位图再看像素），再去怀疑缓存。同名 exe 原地覆盖最容易撞上 Windows 的图标缓存，常规解法是 `ie4uinit.exe -show`、删 `%localappdata%\IconCache.db` 后重启 explorer，或把 exe 改名/换目录再看（这条属通用经验，本轮没在实测里复现）。
2. **路径是相对 csproj 的** —— csproj 在 `app/`，所以 `<ApplicationIcon>AppIcon.ico</ApplicationIcon>` 指的是 `app\AppIcon.ico`；从仓库根跑 `make-icon.ps1` 时默认输出也落在那儿。
3. **资源键大小写** —— `<Resource>` 嵌进去的键保留原文件名大小写（实测 `AppIcon.ico`），而 XAML 编译出的 baml 键是小写（`mainwindow.baml`）。按字节找资源时别只试一种。
4. **PS 5.1 的两个语法坑**（写 `make-icon.ps1` 时都踩了）：`New-Object 类型(参数, 参数)` 会把括号里的列表当成**一个** Object[] 位置参数，报"找不到接受实际参数 System.Object[]"，要用 `[类型]::new(...)`；`SmoothingMode` 在桌面 `System.Drawing` 里没有 `AntiAliasGamma`，只有 `Default/HighSpeed/HighQuality/None/AntiAlias/Invalid`。
5. **单文件发布不受影响** —— `ApplicationIcon` 由 SDK 烤进生成的 apphost，`Window.Icon` 在程序集内嵌资源里，两者都与 exe 放在哪个目录无关。本项目的数据根（`文档\Prompts`）和设置（`%APPDATA%\PromptFavorites`）本来也不在 exe 旁边，所以单 exe 可以任意拷贝。

## 五、本轮实测数据

验证脚本：`tools\verify-icon.ps1`（**未随本包交付**，见本文第六节的落点表更正；2026-10-04 用一份临时 ASCII 脚本手工解析目录头复现了下面"ICO 结构"那一行的结论）。它启动一次应用、直接问 Win32 要结论，然后把**自己起的那个 pid** 结束掉——被强杀的进程不会走 `OnExit`，所以不会写回窗口状态。

| 检查 | 手段 | 结果 |
|---|---|---|
| ICO 结构 | 手工解析目录头 | 7 挡，`type=1 count=7`，各挡偏移连续，`bytesInRes` 与 `w*h*4 + 掩码 + 40` 逐一吻合，末挡正好收到文件尾 |
| exe 图标 | `shell32!ExtractIconEx(-1)` | Debug、自包含单 exe、免运行时单 exe 三处都是 `icon group count = 1` |
| 窗口标题 | `user32!GetWindowText` | `收藏夹` |
| 窗口图标 | `WM_GETICON(0/1/2)` | 小 16x16、大 32x32，句柄非 0；HICON 存成 PNG 看过，就是那枚书签+星 |
| 类图标 | `GetClassLongPtr(GCLP_HICON/HICONSM)` | 都为 0 → 图标走窗口级，不是类级 |
| 对照：删掉 `Window.Icon` | 重新构建 + 同一探测 | 标题栏**仍是同一枚图标** → 证实"回落到 exe 图标"，本文第二节据此改写 |
| 资源键 | 在 dll 里按字节搜 | `AppIcon.ico` 命中（保留大小写）；小写 `appicon.ico` 不命中 |
| 标题编译 | 在 dll 里按 UTF-8 搜 | `收藏夹` 命中，旧串 `Prompt 收藏夹` 已无残留 |
| 体积 | 自包含单 exe | 无图标 70,129,219 → 加图标 70,576,533（.ico 在 apphost 与程序集资源里各一份）→ 文件名带后缀 70,576,670 |
| 回归：自包含 | `publish\PromptFavorites_self_contained.exe --selftest` | 退出码 0，`PASS 断言组=23`（本轮 2026-10-02 的历史实测值；断言组数随 hostile 用例增长，2026-10-04 复测为 `PASS 断言组=29`，退出码契约不变） |
