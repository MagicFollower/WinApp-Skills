# xz / unxz — 高压缩比归档

> xz（LZMA2 过滤器）在常见压缩工具里压缩率最高，`-9e` 用于长期归档；它是单文件压缩器，目录交给 `tar -J`。

## 语法

```bash
xz [选项] [文件...]
unxz [选项] 文件.xz    # 等于 xz -d
xzcat 文件.xz          # 等于 xz -dc
tar -cJf app.tar.xz app/   # tar 归档 + xz
```

## 常用选项

| 选项 | 说明 |
| --- | --- |
| `-0` … `-9` | 预置级别，默认 `-6`；数字越大字典越大、越慢、体积越小 |
| `-e`, `--extreme` | 在所选级别上更慢地换更小的体积，如 `-9e` |
| `-d`, `--decompress` | 解压；`unxz` 即其别名 |
| `-t`, `--test` | 只校验完整性，不输出文件 |
| `-l`, `--list` | 列出 `.xz` 文件的格式、校验类型、过滤器链、压缩前后大小 |
| `-k`, `--keep` | 保留输入文件（默认成功后删除） |
| `-c`, `--stdout` | 输出到标准输出 |
| `-f`, `--force` | 覆盖已存在的输出文件，允许压缩符号链接指向的目标等 |
| `-T`, `--threads=N` | 多线程压缩，`-T0` 用满所有核心；解压并行度受块结构限制 |
| `-M`, `--memlimit=BYTES` | 压缩/解压内存上限，如 `-M512MiB`；超限会拒绝处理 |
| `--lzma2=…` | 手动指定过滤器参数，如 `--lzma2=preset=9,dict=128MiB` |

## 示例

压缩源码归档，`-9e` 适合只需做一次、要长期存放的发布包：

```bash
tar -cf - -C /srv app | xz -9e > app-1.24.0.tar.xz
```

多线程能显著缩短大文件的耗时；`-vv` 会打印实际用到的字典与内存，便于决定级别：

```bash
xz -k -T0 -9 -vv data.iso          # 生成 data.iso.xz，data.iso 保留
```

查看归档元信息，确认校验类型和解压所需内存量级：

```bash
xz -l app-1.24.0.tar.xz
xz -t app-1.24.0.tar.xz && echo "integrity ok"
```

不解压到磁盘，直接把内容接给 tar，或把 `.tar.xz` 转成 `.tar.gz`：

```bash
xzcat app-1.24.0.tar.xz | tar -tf - | head -30
xz -dc app-1.24.0.tar.xz | tar -xf - -C /usr/local/src
xz -dc old.tar.xz | gzip -9 > new.tar.gz
```

## 注意事项

- 高预置级别解压也需要相应内存：`.xz` 头部记录了字典大小，接收方内存不足时 `xz -d` 会直接拒绝，可用 `-M` 明确上限并配合 `--lzma2` 降字典。
- `-k` 之外默认删除输入文件；覆盖已有 `.xz` 需要 `-f`，脚本里建议显式 `-c > out.xz`。
- xz 跳过目录、不压缩多个文件成一体（`xz a b` 只会生成 `a.xz`、`b.xz`），整目录用 `tar -cJf`。
- `-T0` 只对可分块的数据带来加速；从管道读入时块结构受限，收益不如直接给文件名。

## 相关命令

- `tar` — `-J`/`--xz` 把归档交给 xz，大写 J 不可写成 `-j`
- `lzma` — 老的单流格式，xz 也能读写，但已不推荐用于新数据
- `bzip2` — 压缩率略低于 xz、速度也更慢的旧方案
- `zstd` — 体积接近 xz `-3` 量级但速度快一个数量级
