# vmstat — 虚拟内存与整体运行趋势

> `vmstat 1 5` 每秒一行，同时给出运行队列、内存、换页、块 IO 与 CPU 时间分布，适合看趋势而非定位单进程。

## 语法

```bash
vmstat [选项] [间隔(秒)] [次数]
vmstat 1 5         # 每秒一次，共 5 次
```

## 常用选项

| 选项 | 说明 |
| --- | --- |
| `-a` | 内存列改为 active / inactive |
| `-d` | 按磁盘统计已用块与总块 |
| `-p 设备` | 只输出指定磁盘的统计 |
| `-s` | 输出内核事件累计计数表（一次性） |
| `-m` | 显示 slab 分配器信息 |
| `-S 单位` | 内存列按 1K/1M/1G 等换算 |
| `-t` | 每行前加时间戳 |
| `-w` | 宽模式，列宽加倍，避免数字挤成 `*` |

## 示例

采样 5 秒观察整体：

```bash
vmstat 1 5
```

```text
procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu-----
 r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st
 2  0      0 112320  10240 738560    0    0   120   380 4210 6120 18  4 74  4  0
 1  3      0  98112  10240 738624    0    0  8120 24560 9820 12440  9  3 55 33  0
 4  6      0  86592  10240 738704    0    0 12400 31200 11230 15120  7  4 41 48  0
```

`si`/`so` 全为 0 说明没换页；第二行起 `b` 涨到 3、`wa` 涨到 33%，是 IO 阻塞而非 CPU 不够。

只看一次性内核计数，判断上下文切换与中断是否异常：

```bash
vmstat -s
```

按磁盘看块设备使用，不必关心 CPU：

```bash
vmstat -d
```

挂时间戳做长时间记录，事后与业务日志对齐：

```bash
vmstat -t 5 720 > /tmp/vmstat.log
```

## 注意事项

- **第一行是开机以来的平均值**，从第二行起才是区间实测；采样间隔建议 1~5 秒，太短会被瞬时抖动误导。
- `r` = 处于运行态 + 等待 CPU 的可运行任务数（含 D 态之外的排队），持续大于 CPU 核数说明 CPU 吃紧；`b` = 处于不可中断睡眠（D 态）的任务数，`b` 高而 `us` 低几乎一定是磁盘/网络存储卡住。
- `si`/`so` 持续非零才代表真正内存不足在换页；`free` 很低但 `si`/`so` 为 0 是正常状态，可回收缓存都在 `cache` 里。
- `bi`/`bo` 单位是块/秒（块大小由 `-S` 与内核决定，常见 1 KB），`in`/`cs` 是中断与上下文切换次数，异常暴涨常与线程数过多或频繁 `fsync` 有关。

## 相关命令

- `iostat -x 1` — 把 IO 瓶颈下钻到具体设备
- `free -h` — 看 available 判断是否真缺内存
- `pidstat -d 1` / `pidstat -u 1` — 找到造成 `b`/`cs` 升高的进程
- `sar -u` / `sar -r` — 查看 sysstat 采集的历史趋势
