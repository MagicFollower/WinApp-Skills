# uptime — 运行时长与平均负载

> 一行给出当前时间、系统已运行时长、登录用户数与 1/5/15 分钟平均负载。

## 语法

```bash
uptime [选项]
```

## 常用选项

| 选项 | 说明 |
| --- | --- |
| （不带参数） | 打印当前时间、up 时长、用户数、三个负载均值 |
| `-p`, `--pretty` | 只输出可读的运行时长，如 `up 3 days, 4 hours, 12 minutes` |
| `-s`, `--since` | 输出开机时刻，用于判断是否发生过重启 |

## 示例

最常用的一条：

```bash
uptime
```

```text
 14:23:07 up 3 days,  4:12,  2 users,  load average: 0.52, 0.58, 0.61
```

负载是否高必须除以核数，先取核数再判断：

```bash
uptime; nproc
```

```text
 14:23:07 up 3 days,  4:12,  2 users,  load average: 7.90, 6.20, 3.10
8
```

8 核机器上 7.9 已接近满载，且 1 分钟值远高于 15 分钟值，说明压力正在上升。

巡检脚本里只要时长与开机点：

```bash
uptime -p
uptime -s
```

与 `/proc/loadavg` 对照，最后一列是最近调度的 PID：

```bash
cat /proc/loadavg
```

```text
0.52 0.58 0.61 1/234 21455
```

## 注意事项

- 判断基线是 `load average ÷ 核数`：单核 1.0 即满载，8 核要 8.0 才算满；裸看 4.0 在 4 核上是饱和、在 32 核上很空闲。
- 三个值是指数平滑，1 分钟列响应最快。1 分钟 > 15 分钟代表正在恶化，反之代表正在缓解；只看瞬时值容易被单次毛刺误导。
- 负载统计包含处于不可中断睡眠（D 态）的任务，磁盘 hang、NFS 服务端失联都会把负载推得很高而 CPU 却空闲，这时看 `vmstat 1` 的 `b` 列而不是 CPU 使用率。
- 容器里 `uptime` 与 `/proc/loadavg` 读到的都是宿主机的数值，不感知 cgroup 配额。`w` 的首行与 `uptime` 同源，区别在于 `w` 还会列出登录用户、终端、空闲时长与其正在执行的命令。

## 相关命令

- `w` — 谁在登录、空闲多久、正在跑什么
- `vmstat 1 5` — 区分负载来自 CPU 排队还是 IO 阻塞
- `nproc` / `cat /proc/cpuinfo` — 获取核数作为负载基线
- `last -x reboot` — 追溯重启记录
